\begin{abstract}
Sliding-window attention (SWA) gives Transformers a constant per-step KV-cache and
linear-time decoding, but evicted context is lost; linear-attention and state-space
models keep a constant recurrent state yet weaken sharp local retrieval. We present
\textbf{GMSWA}, a single constant-memory attention layer composing an exact local
softmax window with a recurrent gated-delta-rule matrix memory. The branches are
\emph{complementary by construction}: the window attends to the most recent $W$
tokens while the memory ingests \emph{only window-evicted tokens}, so their coverage
partitions causal history with no overlap and no future leakage. The output mixes the
branches by a learned per-position gate $o=\alpha\cdot\text{SWA}+(1-\alpha)\cdot\text{mem}$.
A revised variant (v3) adds separate \emph{NoPE} content-retrieval projections
($\text{mem}_q/\text{mem}_k$) for the memory, decoupling associative recall from rotary
phase and yielding length extrapolation. The layer's state is independent of sequence
length. At 340M parameters / 10B FineWeb-Edu tokens under a shared recipe, GMSWA-v3
attains the lowest next-token loss at every measured position among constant-memory
models, with a margin over SWA that \emph{grows with distance}. Beyond the 2048-token
training length, a same-recipe full-attention Transformer collapses (loss 5.74 then 7.21),
whereas GMSWA-v3 is best of all four models (3.99, 4.04). On single-needle retrieval at
this scale GMSWA-v3 matches SWA --- discrete recall is scale-emergent and weak in
sub-billion base models --- so the 340M memory delivers \emph{soft} utilization (lower
loss) rather than sharp discrete copy; we report this honestly and frame the predicted
recall win as scale-dependent (\pending, 1B). A training-free capacity probe explains the
bilinear rank wall motivating a recall-versus-memory frontier on which GMSWA is positioned.
\end{abstract}

\noindent\textit{Keywords}: sliding-window attention; constant-memory inference;
linear attention; gated delta rule; long-context language modeling; length extrapolation.

\section{Method}
\subsection{Overview}
Each layer fuses two branches by a learned per-position sigmoid gate:
\begin{equation}
o_t = \alpha_t \, o_{\text{local}}[t] + (1-\alpha_t)\, o_{\text{mem}}[t].
\end{equation}
A single projection $\mathrm{Linear}(d,3H)$ yields, per head, the write strength $\beta$,
log-decay $g$, and mix coefficient $\alpha$.

\subsection{Local Branch --- Exact Sliding-Window Attention}
\begin{equation}
o_{\text{local}}[t] = \mathrm{softmax}\!\left( q_t K_{[t-W+1:t]}^\top / \sqrt{d} \right) V_{[t-W+1:t]}.
\end{equation}
Implemented via \texttt{flash\_attn\_func(causal=True, window\_size=(W-1,0))} with an
equivalent SDPA${+}$mask fallback. Local cache $=W\,H_{kv}\,2\,d$, constant in $T$.

\subsection{Memory Branch --- Gated-Delta-Rule Matrix Fast Weight}
Each query head holds $S\in\mathbb{R}^{d\times d}$. A token is written \emph{only on
eviction} from the window, with key $\hat{k}_e$ and value $v_e$:
\begin{equation}
S_t = e^{g_t}\!\left( S_{t-1} - \beta_t S_{t-1}\hat{k}_e \hat{k}_e^\top \right) + \beta_t v_e \hat{k}_e^\top,
\qquad o_{\text{mem}}[t] = S_t\,\hat{q}_t .
\end{equation}
Training uses FLA's \texttt{chunk\_gated\_delta\_rule} (exact backward); decoding uses an
inline path. Memory state $=H_q\,d\,d$, constant in $T$.

\subsection{Complementary Coverage}
Eviction \emph{is} the write event, so at step $t$ the memory holds $[0,t{-}W]$ and the
window sees $[t{-}W{+}1,t]$: disjoint sets covering $[0,t]$ exactly. Verified bit-exactly
(no future leakage) and by prefill/decode consistency (cosine $1.0$).

\subsection{NoPE Content-Retrieval Projections (v3)}
Separate position-free $\text{mem}_q/\text{mem}_k$ projections let the memory retrieve by
content, independent of rotary phase; with corrected gate init ($\alpha\!\approx\!0.98$ at
start), training begins near pure SWA and learns to use memory. This drives extrapolation.

\subsection{Constant-Memory Analysis}
Per-layer state $=$ local ring buffer $+$ matrix memory, both independent of $T$, versus
full attention's linearly growing KV-cache.

\subsection{Why Bilinear: the Rank Wall}
Under the test-time-regression view, storing $D$ associations needs state rank $\approx D$,
i.e.\ $O(D^2)$ entries --- the rank wall (probed in Sec.~\ref{sec:probe}). Hence the memory
is a \emph{soft} summarizer; the window owns sharp local retrieval.

\section{Mechanism Capacity Probe}\label{sec:probe}
Training-free: store $D$ key$\rightarrow$token associations at fixed state, query, decode,
measure exact-token recall vs.\ $D$. Bilinear (linear/delta) hits a rank wall ($O(D^2)$ for
$D$ associations); a hash/sketch store escapes it ($O(D)$), advantage growing under load.
The capacity-winning hash store is \emph{not} reliably trainable (hard/soft addressing),
so it is used as a diagnostic, not the deployed mechanism. Canonical values \pending\ (clean
re-run from \texttt{mech\_capacity.py} for camera-ready).

\section{Analysis and Discussion}
\subsection{Recall--Memory Frontier}
Memory budget vs.\ discrete-recall capacity: bilinear stores sit below a rank-wall ceiling,
sketch stores raise it but are untrainable, an exact window is perfect within its span and
zero beyond. GMSWA composes both regimes; the frontier predicts scale-dependent sharpening
of soft utilization into discrete recall.
\subsection{Why Extrapolation Works}
Window sees only in-distribution offsets ($\le W$); memory retrieves by content (NoPE),
independent of rotary phase --- so GMSWA degrades gracefully where rotary attention breaks.
\subsection{Honest Scale Caveat}
At 340M: real, measured soft-utilization win; \emph{no} discrete-recall claim. Discrete recall
is the explicit 1B \pending\ test.

\section{Conclusion and Future Work}
GMSWA: constant-memory exact window $+$ complementary content-retrieving gated-delta-rule
memory on evicted tokens. Lowest loss at every position among constant-memory models
(margin grows with distance), best-of-all beyond training length where rotary attention
collapses, at sequence-length-independent state. Honest soft-vs-discrete caveat at 340M,
explained by a rank-wall/frontier analysis. Future: 1B discrete-recall run; same-recipe
GDN/GLA/Mamba-2 baselines; evicted-only ablation; frontier sweep; fused-kernel efficiency.
